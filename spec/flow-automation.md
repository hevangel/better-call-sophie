# Automating Google Flow with AI agents

**Status:** LOCKED direction (showrunner, 2026-11-22). Setup **works on the showrunner's Windows computer** as of 2026-11-22: login, `projects`, `read`, `options` and `download` ran. Direct generation through AAO is **broken** (gap 7), so the first image (the office master) was generated by playwright-cli in an AAO-created project. The **first video clips** (the D01 commercial's six shots) were generated on 2026-11-23 by playwright-cli in the show project, with `@Sophie Goodman` in the prompt (see "Characters and media in prompts" below).

**Goal:** Claude (or another coding agent) drives Google Flow and Google Flow Music, downloads the results, checks them against the shot record, and logs provenance. The showrunner approves creative choices and handles Google sign-in. Quality is not the concern yet: the goal is a repeatable loop. Other generation tools can be added later behind the same loop.

## The tool: any-agent-orchestrator (AAO)

`external/any-agent-orchestrator` is the showrunner's own repository ([hevangel/any-agent-orchestrator](https://github.com/hevangel/any-agent-orchestrator)), pinned as a submodule (see [third-party.md](third-party.md)). It drives websites with **playwright-cli** and the user's installed **Google Chrome**, using saved browser profiles. Its Flow driver is `src/orchestrator/web_flow.py`, and its Flow Music driver is `src/orchestrator/web_flow_music.py`. Its documentation is `spec/web_interfaces.md` (section "Google Flow").

This is browser automation of the Flow website. It is **not** a Google API. Use only commands that AAO actually implements, and check `uv run aao flow options` against the live page before trusting any list of models or settings.

### Commands available at the pinned revision (`00ba249`)

Run these from `external/any-agent-orchestrator` with `uv run`:

| Need | Command | Credits |
| --- | --- | --- |
| Check the Google login | `aao flow status` | free |
| List or create projects | `aao flow projects`, `aao flow new --title "..."` | free |
| List media in a project | `aao flow --json read <project> [--type video\|image]` | free |
| Download the original file | `aao flow download <project> <media> --to DIR` | free (`--quality original`) |
| Upload reference images | `aao flow upload <project> <file>...` | free |
| Create a character | `aao flow new-character <project> --name NAME (--image FILE \| --prompt TEXT) [--info TEXT] [--voice NAME]` | free with `--image` |
| Read the live model and settings choices | `aao flow options [--project P]` | free |
| Generate one image or video and download it | `aao web image\|video flow --prompt "..." [--reference IMG]... --out DIR` | spends credits |
| Generate one song as an MP3 | `aao web audio flow-music --prompt "..." --out DIR` | spends Flow Music quota |

The showrunner uses a subscription plan, so cost does not limit tests. Still use one output per generation, and log every generation.

### Gaps in AAO that block parts of the demo

These are confirmed by reading the pinned code. They belong in AAO, the upstream repository, not in this repo. Do not work around them by editing the submodule in place.

1. **Generation settings:** `aao web video flow` creates its own "AAO video …" project and exposes only the prompt, the references (at most 3 ingredients) and the aspect ratio. It cannot choose the model, resolution, duration or count, or generate inside a named project such as `Better Call Sophie - Flow Experiments`.
2. **Characters in prompts:** there is no way to use `@Sophie Goodman` (a saved Flow character, with its voice) in a generation.
3. **Reading characters:** there is no command that reads a character's name, ID, image, info text or voice. This blocks syncing Flow characters back to the repo.
4. **Editing characters:** there is no way to update an existing character's info text or voice.
5. **Frames, Extend, Scenebuilder:** there is no driver for start/end frames, Save frame, Extend, or Add to scene and scene download.
6. **Flow Music controls:** the prompt is the only input. There are no lyrics, style, length or instrumental controls, and the first finished song is downloaded.

7. **Broken direct generation (found 2026-11-22):** `aao web image|video flow` looks for a button named "Flow Agent", but the live page labels it "Flow agent". The command creates its project and then times out before generating. Fix the label in AAO upstream (`web_flow.py`, `generate-prepare`).
8. **Character media:** `aao flow download` times out on a character tile, because a character's "More options" menu has no Download item. Read the character page's image instead (see [Sophie's Flow record](../assets/characters/sophie-goodman/flow-character.md)).
9. **Stale page state:** AAO doesn't reload a page that is already open at the target URL, so a scrolled page or an open menu left by an earlier command can break the next one. Sending the browser to `https://flow.google.com/` first clears it.

All of these, plus the stale `aao flow options` list, are filed upstream as [hevangel/any-agent-orchestrator#9](https://github.com/hevangel/any-agent-orchestrator/issues/9) (2026-11-22).

Until a gap is closed, that step is done **by hand in Flow**, and the result is still logged here.

### Characters and media in prompts (by hand, found 2026-11-23)

Until AAO closes gap 2, this is how the D01 shots used Sophie's character, driven with playwright-cli in the show project:

1. Composer settings: **Video**, **Ingredients**, 16:9, 720p, x1, model picker "Omni 1.2 Flash". The summary then reads "Video · 720p · 8s".
2. In the prompt box (a ProseMirror editor), typing `@` opens an asset picker with a **Search assets** box and tabs (All, Images, Videos, Voices, Characters, Avatars, Uploads).
3. Search the name. A **character** shows a preview (its image variants and voice) and needs **Add to prompt**; an **image** is inserted as soon as it is clicked.
4. Each mention becomes a chip with `data-mention-id` (the character ID, or the media ID) and also adds an ingredient. Flow adds a space after each chip.
5. **Clear prompt** (beside the ingredients) removes leftover chips and ingredients before the next shot.

Generation took about 45–55 s per 8-second clip. `aao flow download <project> 1` then fetched the MP4 (1280x720, 24 fps, AAC stereo). The checks used [scripts/check_lines.py](../scripts/check_lines.py) (Whisper) and ffmpeg contact sheets.

## Where it runs

Google sign-in needs a real Chrome window that the showrunner can see. The showrunner signs in once with `uv run aao web login gemini` (Flow shares the Gemini login) and once with `uv run aao web login flow-music`. Agents never type passwords or 2FA codes.

- **Supported:** the showrunner's own computer (Linux, macOS or Windows), running Claude Code locally in a checkout of this repo, with the AAO prerequisites installed (uv, Node.js and playwright-cli, Google Chrome, and herdr, which is optional for Flow).
- **Not supported:** a Claude Code cloud container. It has no visible browser for the human sign-in, and Google may reject sign-in from datacenter IPs. A cloud session can plan, write prompts and logs, and review files that are committed or uploaded to it, but it cannot drive Flow.
- **Remote Control:** a cloud session can drive a folder on the showrunner's computer through Remote Control. On 2026-11-22 the computer `sidonia` listed folders, but none were offered to cloud sessions: the folder may be in a hidden directory, or the Claude app may need an update.

## The automated shot loop

For each shot:

1. **Shot record:** `production/shot-lists/<id>.md`, using the YAML template in [production-pipeline.md](production-pipeline.md). It holds the prompt, the references and the target length.
2. **Generate:** `aao web video flow --json --prompt "<prompt text from the record>" --reference <img> --out <dir>` with the shot's references. If AAO cannot do the shot (gaps 1–5 above), generate it by hand in Flow.
3. **Intake:** download the original into production storage (`production/exports/<id>/`, which Git ignores). Record the original file name, a SHA-256 checksum, and the duration, resolution and frame rate from `ffprobe`.
4. **Automatic checks** (by the agent):
   - **Frames:** extract frames with ffmpeg into a contact sheet, and compare the face, hair, wardrobe, props and set against the character and location reference packs.
   - **Speech:** transcribe the speech (Whisper, `external/whisper`) and compare it word by word with the scripted line.
   - **Technical:** check the length, aspect ratio and audio level, and look for text, logos or subtitles burned into the frames.
5. **Log:** write a `production/generation-logs/<id>-vNN.yaml` record with the actual settings shown in Flow, never guessed ones, plus the check results and any uploaded YouTube link.
6. **Status:** the agent may set a take to `generated` or `rejected`. Only the showrunner sets `selected` or `final`.

Project-owned helpers so far: [scripts/check_lines.py](../scripts/check_lines.py) (Whisper line check, step 4) and [scripts/chalk_overlay.py](../scripts/chalk_overlay.py) (text on a surface, in post). Whisper runs from the submodule with `uv run --no-project --with ./external/whisper`; on Windows its model download can fail with an OpenSSL error, so fetch the model file with curl (see the script's docstring).

## Distribution

Demo and test videos are published on the YouTube channel **[@better-call-sophie](https://www.youtube.com/@better-call-sophie)**. AAO does not drive Flow's **Publish to YouTube** menu. Since 2026-11-23 agents upload through **youtube-mcp** (`external/youtube-mcp`, [third-party.md](third-party.md)) with [scripts/youtube_mcp.py](../scripts/youtube_mcp.py): preflight, the showrunner's approval of the preview, then the upload; then a metadata update for tags, category, "made for kids" and altered or synthetic content. It needs the showrunner's own Desktop OAuth client and one browser sign-in (Testing mode expires after 7 days); settings live in `~/.config/youtube-mcp/env`, never in the repo. Uploading by hand in YouTube Studio still works.

Sign-in on Windows (learned 2026-11-23):

- youtube-mcp v0.3.3 opens the Google link with `cmd /c start`, which cuts the URL at the first `&` ("Error 400: invalid_request, Required parameter is missing: response_type"). Run the sign-in through the preload [scripts/youtube_auth_win.mjs](../scripts/youtube_auth_win.mjs), which opens the full link and also prints it: `node --import ./scripts/youtube_auth_win.mjs external/youtube-mcp/dist/index.js youtube-auth [--force]`, with the settings from `~/.config/youtube-mcp/env` in the environment. The submodule is not patched; the bug belongs upstream.
- The showrunner's Google account has more than one channel. On Google's "choose an account or brand account" screen, pick **BetterCallSophie**. A sign-in for the wrong channel shows up as `ownership_required` on the first preflight; `youtube_my_account` shows which channel is connected. Re-run the sign-in with `--force` to switch.
- A preview can go stale when YouTube updates the video (for example right after processing) or expire after a few minutes. Preflight again, check that `desiredFingerprint` matches the approved preview, then approve and apply. Record each video's URL in its generation log. Keep the "unofficial fan work" and "AI-generated" disclosures from [ai-creative-policy.md](ai-creative-policy.md) in the video descriptions.
